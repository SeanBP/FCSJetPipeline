# hcal_gain_corrections

Retroactive HCAL per-tower gain-correction machinery for `data_to_jet`.

**Why this exists**: `StFcsDb`'s real, DB-sourced `getGainCorrection()`
for HCAL is currently a flat `1.0` placeholder for all of Run 22 -- there
is no real per-tower HCAL calibration in the conditions DB yet (ECAL, by
contrast, already has a genuine per-tower correction). Once STAR's FCS
calibration group measures real per-tower HCAL corrections,
`data_to_jet`'s already-produced SimpleTree files need those corrections
applied retroactively, since the muDst hit energies they were built from
won't be reprocessed. This folder lets `StSimpleReaderMaker` apply a
per-channel multiplicative correction itself, at SimpleTree-forming time,
sourced from a plain text file here instead of the DB.

**Current status**: DB-verified no-op. `manifest.txt` and its correction
file(s) are auto-generated by
`GainPlayground/scan_hcal_gain_db/scan_hcal_gain_db.C`, which scanned the
real conditions DB and confirmed HCAL's `getGainCorrection()` is flat
`1.0` for every real channel across all of Run 22 -- one period, no
detected changes. The machinery is fully wired up and active
(`data_to_jet/runMudst.C` calls `SetHcalRetroactiveGainCorr()`
unconditionally), but has zero effect on output as long as the scanned
values stay `1.0`.

## Files

- **`manifest.txt`** -- maps date ranges to correction-factor files. One
  row per period: `startDate endDate filename` (`YYYYMMDD`,
  `[startDate, endDate)`, same convention `St_db_Maker`/`StDbLib` use
  elsewhere in this project). The first matching row wins.
  Auto-generated -- see "Regenerating" below, don't hand-edit.
- **`hcal_gain_corr_<startDate>.txt`** (one per detected period) -- the
  actual correction factors, one line per real HCAL channel:
  `ehp ns dep ch factor` (`ehp=1` always, since this is HCAL-only; format
  matches `StFcsDb`'s own `readGainCorrFromText()` gain-correction text
  format exactly). 520 rows each (260 channels x 2 sides).
- **`generate_placeholder.C`** -- lighter single-snapshot generator (one
  file, all `1.0`, no DB scanning/period-detection) -- a manual fallback
  if `scan_hcal_gain_db.C` isn't available or a quick reset is needed.
  Enumerates channels the same official way (`for id in 0..maxId(det):
  getDepfromId(det,id,...)`) so its output is format-identical.

## Regenerating (including once real per-tower HCAL corrections exist)

Run `GainPlayground/scan_hcal_gain_db/scan_hcal_gain_db.C` (see that
folder's README.md) -- it queries the real conditions DB across Run 22,
detects real calibration-period boundaries (wherever any channel's value
actually changes between sampled dates), and writes both the
correction-factor file(s) and this folder's `manifest.txt` directly,
automatically. No code changes needed in `StSimpleReaderMaker` -- it
always reads whatever the current `manifest.txt` says. The scanner backs
up the existing `manifest.txt` to `manifest.txt.bak` before overwriting it.

## How it's applied

`StSimpleReaderMaker::Make()` resolves each event's real date directly
from the muDst (`StMuEvent::eventInfo().time()`, no DB query needed),
picks the correction file whose manifest period covers that date, and
multiplies each HCAL hit's already-read energy
(`Cal_hit_energy[Cal_nhits] = hit->energy();`) by the per-channel factor
looked up via `StFcsDb::getDepfromId()`. This happens once, right when
the SimpleTree's `Cal_hit_energy` branch is filled -- i.e. retroactively,
without needing the underlying muDst reconstruction to change. Not wired
into `sim_to_jet`: simulated events already get real, live
`getGainCorrection()` straight from `StFcsDb` at simulation time (see
`GainPlayground/README.md`), so there's nothing to retroactively fix
there.
